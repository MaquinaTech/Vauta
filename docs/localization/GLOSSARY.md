# Vauta glossary for translators

Canonical English terms used in Vauta's interface, what they mean, and how to treat them.
Translate each term **one way** and use it everywhere: in buttons, settings, errors,
notifications and exports. If a term already has an official Apple translation in your
language (System Settings, Keychain, Login Items, Touch ID prompts, Privacy & Security…),
use Apple's wording: check how macOS itself says it in your language, or Apple's
localization glossaries (Apple Developer downloads).

See [TRANSLATING.md](../TRANSLATING.md) for the workflow.

## Do not translate

Keep these exactly as written, in Latin script, in every language:

- **Vauta** (the app name; never translate it as "minutes" or "record")
- **Earlier versions.** User-visible text never names Vauta's former working title. Where a string refers to data or files from before the rename, say "an earlier version": es "una versión anterior", fr "une version antérieure", de "einer früheren Version", it "una versione precedente", pt-BR "uma versão anterior", ja "以前のバージョン", ko "이전 버전", zh-Hans "早期版本".
- **Apple Intelligence**, **Touch ID**, **macOS**, **Mac**, **Siri**, **VoiceOver**, **FaceTime**
- Meeting apps and browsers: Zoom, Microsoft Teams, Google Meet, Slack, Webex, Discord,
  Jitsi Meet, Whereby, Amazon Chime, GoTo Meeting, Safari, Chrome, Edge, Firefox, Arc,
  Chromium, WebKit, Gecko
- Model servers and models: LM Studio, Ollama, llama.cpp, MLX, vLLM, Jan, LocalAI, Qwen, EmbeddingGemma, Gemma, Hugging Face, Google (as the model's maker),
  OpenAI (in "OpenAI-compatible", translate only "compatible")
- Formats and technologies: JSON, Markdown, PDF, SRT, WebVTT, PEM, HTTPS, HTTP, URL,
  SHA-256, SPKI, base64, AES-256, SQLite, Tailscale, M4A, MP3, WAV, AIFF, MP4, MOV
- Technical values shown as-is: `enable_thinking`, `chat_template_kwargs`,
  `reasoning_effort`, `/v1`, `127.0.0.1`, `::1`, `localhost`, `https://`, `*.local`,
  commands such as `Vauta cert-pin cert.pem`
- Keyboard symbols: ⌘ ⌃ ⌥ ⇧

## Style rules

- **Capitalization.** English follows macOS: title case for buttons, menu items,
  tabs, window titles ("Erase All Meetings…"), sheet titles and empty-state titles
  ("Back Up Meetings, Context and Settings"); sentence case for section headings inside a window
  ("Keeping meetings"), form labels, descriptions and messages. A title that is a question or a full
  sentence is in sentence case wherever it appears, in an alert, a confirmation dialog or a sheet
  ("Delete this decision?", "Erase all meetings and context?", "Couldn’t save the person"; empty-state titles are in title case even when they are sentences ("Meetings Are Locked", "Your Data Couldn’t Be Opened"); question titles of alerts and confirmation sheets stay in sentence case ("Erase all meetings and context?") while a task sheet title is in title case ("Export Meeting"), and the panel warning "Your data couldn’t be opened" stays in sentence case because it is a message, not an empty-state title).
  In title case, short prepositions stay lowercase ("Restore from a Backup", "Merge “%@” into
  Another Project", "Set Up a Model Server"), as in Apple's menus; a verb's own particle
  keeps its capital ("Merge Into…"). A sheet title and a card heading never say the same words in two casings: the card heading is a sentence ("Better minutes with a model server") and the sheet title is an action ("Choose How to Write Minutes"; a finished sheet may name its result, "Model Server Ready"). In your language, follow Apple's conventions for macOS in that language
  (most use sentence case everywhere; German capitalizes nouns; there is no case in
  Japanese, Korean or Chinese). Brazilian Portuguese uses sentence case everywhere too
  (buttons, menu items, headers, toggles, empty-state titles: "Pular configuração",
  "Perguntas em aberto"); only proper names and macOS pane names keep capitals
  ("Ajustes do Sistema", "Privacidade e Segurança", "Chaveiro", "Reuniões" as the window).
  The name of the feature, **Live Translation**, keeps its capitals everywhere in English (it is a proper name, like
  Apple's "Live Captions": the menu-bar panel card, Settings and the shortcut list all say it the same way); "Live
  notes" is a section, not a feature, and stays in sentence case. The language pair ("Spanish → English") is a label:
  each language name starts with a capital in the chip, the titles and the download status, in every language.
- **Help tags (`.help`).** One form everywhere: an imperative sentence-case phrase with no final period
  ("Show the stored translation in gray under each line of “Others”", "Cite the highlighted transcript
  passage, if there is one"). A tag of two sentences keeps its periods. In your language use the form Apple
  uses for tooltips (the infinitive in es, fr, de, pt-BR; the imperative in it).
- **VoiceOver labels of buttons.** The same words and the same casing as the visible button or menu item
  ("Pause Translation", "Turn Off Live Translation", "Show Transcript", "Start Recording"), so a spoken label and the
  title a sighted person reads never differ. A label that names a value or a region rather than an action
  ("Download progress") is a description and stays in sentence case.
- **Product names never break.** "Apple Intelligence" is written with a no-break space (U+00A0) in every localized string, so it never splits across two lines. Keychain: it and pt-BR use the capitalized macOS name (it "Portachiavi", pt-BR "Chaveiro") everywhere, and lowercase only in the login keychain (it "portachiavi login", pt-BR "chaveiro de início de sessão").
- **Ellipsis.** A trailing "…" (one character, U+2026) on a button or menu item means it
  opens a dialog, a sheet or a file panel, or asks for more input ("Back Up…", "Set Up…" that
  opens the guide). A button that only goes to a window or a Settings pane has no "…"
  ("Ask", "Meetings", "Show Models Pane", "Change"). Use "…" also for progress ("Saving…").
  German follows Apple's macOS style: a no-break space (U+00A0) before the ellipsis
  ("Löschen …", "Einrichten …"), so the "…" never wraps alone onto a new line. All other languages: no space.
- **Captions.** The floating translation window is "the captions" (or "captions") once Live Translation is the context, never
  "live captions": that is Apple’s own accessibility feature, Live Captions, a different thing. "Live Translation" names the
  feature; "the captions" names what it shows ("The captions keep Apple’s translation on screen"). The same in every
  language: one word for the captions, with no "live" in front of it.
- **Disk space.** One verb phrase everywhere: "Free up space" (and "Free up at least %@" when an amount is known).
- **Terms.** The app that runs a model is always "the model server app" (or its name, LM Studio, Ollama); never "model app" or "server app". Buttons that go to a pane of Vauta's own Settings read "Show <Pane> Pane" ("Show Models Pane", "Show Calendar Pane", "Show Context Pane": the People card’s button that opens that entry in the editor is the last one), and the prose that points to such a pane says "in the Context pane", never "Settings → Context", next to such a button, so they never look like the buttons that open a System Settings pane. The generic key "Show %@ Pane" reads es "Mostrar el panel %@", fr "Afficher le volet « %@ »", de "Bereich „%@“ anzeigen", it "Mostra il pannello %@", pt-BR "Mostrar o painel %@", ja "「%@」ペインを表示", ko "%@ 패널 보기", zh-Hans "显示“%@”面板". Those all read "Open <Pane> Settings" ("Open Sound Settings", "Open Login Items Settings", "Open Users & Groups Settings") and each language uses one pattern for all of them. Context (the feature and its pane) is always zh-Hans 背景信息; 上下文 is only the model’s context window (上下文大小, 上下文长度). "Finished sentence" (live captions) uses one word per language: de abgeschlossen, ja 確定した, ko 완료된, zh-Hans 已完成的. US spelling in English ("Acknowledgments", "Canceled"). In de/es/fr/it/pt-BR the last two words of every help text are joined with U+00A0 so no paragraph ends on a one-word line; the backup button reads es "Hacer antes una copia de seguridad…" and de "Zuerst Backup erstellen …"; the language pair (%@) is always bare, never quoted and never wrapped in "the languages", in every caption state (needs a download, downloading, didn’t finish, isn’t available, couldn’t translate); because the pair starts with a capitalised language name, the download states put it first as a label and never after a preposition or verb: es "%@: descargando…" / "%@: descarga sin terminar", it "%@: download in corso…" / "%@: download non terminato", pt-BR "%@: baixando…" / "%@: download não concluído", de "%@: Download unvollständig", fr "%@ : téléchargement en cours…"; de "%@ benötigt einen Download". "Voice recognition" (who is speaking, the Speakers pane) is not "Speech recognition" (the transcription engine): es "Reconocimiento de voces" vs "Reconocimiento de voz", fr "Reconnaissance des voix" vs "Reconnaissance vocale", it "Riconoscimento delle voci" vs "Riconoscimento vocale", pt-BR "Reconhecimento de vozes" vs "Reconhecimento de fala". In ko the Show %@ Pane button and the prose that names a pane both quote the pane name (“컨텍스트” 패널). In ja a number and its counter (%lld件) are joined with U+2060, and model names such as "pyannote community‑1" use a no-break space; in fr/pt-BR "e‑mail" and imperative + pronoun forms use a non-breaking hyphen (U+2011); in ko "이 Mac" is joined with U+00A0.
- **Buttons that go somewhere.** One verb per kind of destination. A pane of Vauta’s own Settings: "Show <Pane> Pane". A window of Vauta: "Open <Window>" ("Open Meetings", "Open Network Activity"; the Window menu keeps the window names). A System Settings pane: "Open <Pane> Settings". The exception is a task button, which names the fix and not the place: "Change Shortcut" is the label wherever a recording shortcut taken by another app is reported (panel, setup and the Status row), although it opens Settings → General.
- **Descriptions.** Text that explains a row, a card or a sheet (Settings rows, the recommendation row, sheet warnings and footnotes) flows as one paragraph, whatever the number of sentences (`Text(description:)`, `SheetFootnote`). One sentence per line (`SentenceLines`) is only for the stacked, centred messages of setup, the model guide and the panel cards, where each message is short and stands alone.
- **Quotation marks.** English uses “curly quotes” around names and titles. Use your
  language's quotation marks, consistently inside one language: « » with no-break spaces
  in French, „ “ in German, « » in Spanish, “ ” in Italian, Portuguese (pt-BR), Korean and
  Simplified Chinese (zh-Hans), 「 」 in Japanese (and in Traditional Chinese, zh-Hant).
  Quote the name of a mode or pane when it is the subject of a sentence (see Ask).
- **Paths to settings.** "Settings → Models" names Vauta's panes; "System Settings →
  Privacy & Security → Microphone" names macOS panes (always with "System Settings", so it
  is never confused with Vauta's own Privacy & Security pane). Translate each part with
  Vauta's pane names and Apple's names for macOS panes in your language. The one exception is
  a message shown next to an "Open System Settings" button (the microphone and screen-recording
  failures): it names only "Privacy & Security → Microphone", because the button already opens
  System Settings and the full path would not fit the narrow panel banner on one line. A macOS notification (the microphone failure that arrives while Vauta is in the background) keeps the full path: it has room, and it is read away from Vauta, so it names the whole route. The
  "Open System Settings" button of a privacy pane (Microphone, Screen & System Audio Recording,
  Calendars, Notifications) stays generic; the "Open <Pane> Settings" pattern below is for panes
  that are not about a permission. Use "→" for every
  path and put a no-break space (U+00A0) on both sides of it, so a line never starts with
  an arrow or splits the path. `scripts/check-strings.sh` fails on a plain-space arrow.
- **Placeholders.** Every `%@` (text) and `%lld` (number) must stay, exactly once each.
  When the word order needs them in another order, number all of them:
  `%1$@`, `%2$@`, `%1$lld`… (if one placeholder in a string is numbered, number them
  all). `%%` is a literal percent sign. `%#@name@` in `.stringsdict` files is a plural
  variable; keep its name unchanged.
- **Plurals.** Never build plurals by hand. Use the categories your language needs
  (`zero`, `one`, `two`, `few`, `many`, `other`) in `Localizable.stringsdict`; `other` is
  always required. A form may leave out the number ("once") when that reads better.
- **Tone.** Short, plain, calm. Say what happened and what to do. Address the user the
  way Apple does in your language (for example "tú" in Spanish, "vous" in French, "du"
  in German, polite forms in Japanese and Korean). Use one register in the whole language:
  German is always "du" (no "Sie", "Ihr", "Ihnen"; imperatives "Öffne", "Wähle"); Korean
  uses the polite "-세요" ending for requests (not "-십시오").
- **The app name.** "Vauta" is a proper noun: never put an article before it (pt-BR
  "Vauta não tem permissão", "Ajustes de Vauta", "Boas-vindas a Vauta"; not "o Vauta"). Rephrase
  rather than add an article or gender ("o app Vauta" only if the sentence needs a noun). This holds in every language:
  pt-BR "Vauta não usa", never "o Vauta".
- **Units and numbers.** "min" and "s" are abbreviations of minutes and seconds; use your
  language's usual abbreviations. Numbers, dates and sizes are formatted by macOS.
- **Line breaks.** A translation never contains a forced line break (`\n`) that the English value does not have: the layout wraps the text, and a fixed break goes wrong at other widths and font sizes. `scripts/check-strings.sh` fails on it.
- **Length.** Buttons, tabs, menu-bar states and badges have little room. Prefer the
  shortest natural wording; check the result in the app.
